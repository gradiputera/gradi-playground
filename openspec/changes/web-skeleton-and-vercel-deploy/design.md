# Design

## Context

`apps/web/` contains only a README. No Node project exists in the repository yet, so there is no workspace, lockfile or Node CI. The Supabase platform layer is applied to the hosted project. Its auth settings are done, except the URL configuration, which waits for the deployed URL (see proposal.md, Why).

Constraints that shape the approach:
- ADR 0003: the web app deploys natively on Vercel. It is not containerized.
- ADR 0008: `/` is SSR, `/playground/**` is CSR, and both modes come from Nuxt `routeRules`.
- ADR 0002: no Turborepo or Nx; the pnpm workspace is added now because this is the first Node project.
- Node.js 26 is the current LTS (26.13.1). Vercel made it generally available for builds and functions, and it is the default for new projects. Nuxt 4.6.4 accepts `>=26.0.0`. The owner installs Node with nvm.

Every file in the Appendix was run in a scratch prototype on 2026-11-22, with the exact pinned versions below. `pnpm install`, `nuxt typecheck`, all 11 e2e tests and `nuxt build` passed. The tasks copy these files verbatim, so the implementer makes no design choices.

## Goals / Non-Goals

**Goals:**
- A production build that Vercel deploys with no configuration beyond the root directory and one build flag.
- The rendering contract (SSR versus CSR), the headers, the 404 and the health endpoint verified by automated tests against a real production build.
- A layout the auth change can extend: BFF routes under `server/`, and page content separated from markup.

**Non-Goals:**
- Visual design beyond a clean, readable baseline. There is no UI framework and no web fonts.
- Any runtime configuration or environment variables. The app reads none in this change.
- Browser-driven end-to-end tests. Playwright arrives with the interactive playground features.

## Decisions

### D1. Workspace layout

```

  package.json          name "web", exact pins, engines node 26.x                                 (A3)
  tsconfig.json         Nuxt 4 project references                                                 (A4)
  nuxt.config.ts        route rules and headers                                                   (A5)
  vitest.config.ts                                                                                (A6)
  app/
    app.vue                                                                                       (A7)
    layouts/default.vue header and footer                                                         (A8)
    assets/css/main.css system font stack, light and dark                                         (A9)

  test/e2e/web.test.ts                                                                            (A17)
```

`app/content/profile.ts` holds the main page content so the owner edits data, not markup. Every value comes from facts already public in the repository: the GitHub handle `gradiputera`, the repository link, the stack and what the project demonstrates. The introduction is a visible placeholder marked `TODO(owner)`. Nothing personal is invented.

pnpm 12 fails the install (`ERR_PNPM_IGNORED_BUILDS`) when a dependency's build script is not approved. In the prototype the only one was `esbuild`, so `pnpm-workspace.yaml` allows exactly that one through `allowBuilds`.

Alternatives: Nuxt Content is rejected as a heavy dependency for one page. Keeping the content inline in `index.vue` is rejected because it mixes the owner's text with layout.

### D2. Rendering and headers through `routeRules` (A5)

- `/**` gets the four security headers.
- `/playground` and `/playground/**` get `ssr: false` plus `X-Robots-Tag: noindex`.
- `/api/health` gets `Cache-Control: no-store`.

Each specific rule repeats the security headers itself, so correctness never depends on how Nitro merges overlapping rules. `/playground` is listed next to `/playground/**`, so the rule never depends on whether `**` matches zero segments. On Vercel, the Nitro `vercel` preset is detected automatically and applies the same rules.

Other settings: `compatibilityDate: '2026-11-21'`, `telemetry: false` (no prompt, nothing sent), `devtools: { enabled: false }`, and the global stylesheet.

Not-found behaviour (checked in the prototype):
- An unmatched route outside `/playground` is server-rendered as `app/error.vue` with HTTP 404.
- Under `/playground/**`, the server returns the SPA shell with HTTP 200, and the client router renders the same `error.vue`.
- A request that does not accept HTML (for example `curl` without an `Accept` header) gets the 404 as JSON. Browsers send `Accept: text/html`, so the test sends it too.

Alternatives: a `server/middleware` that sets headers is rejected, because route rules also reach Vercel's routing layer and stay declarative. `nuxt-security` is rejected for now: it is a full module with a CSP generator, and the CSP waits for the auth change.

### D3. Main page metadata and hydration

`index.vue` calls `useSeoMeta` with the `profile.seo` values. Pages render only static data: no `Date.now()`, no randomness and no browser-only APIs during render, so hydration cannot mismatch (an ADR 0008 risk).

### D4. Tests: `@nuxt/test-utils` e2e against a production build (A17)

One test file calls `setup({ rootDir, server: true, build: true })` once. That builds the app and starts the real Nitro server, so the tests see the same output Vercel deploys. One file means one build, which takes about 15 seconds. Its 11 tests map onto the spec scenarios:
- **Main page**: `/` is server-rendered with the `<h1>`, the call to action and `href="/playground"`; it has a title and a meta description; it has no `X-Robots-Tag`.
- **Playground**: `/playground`, `/playground/payment` and `/playground/dashboards` each return HTTP 200 with the empty mount point `<div id="__nuxt"></div>`, without the hub link (which proves there is no server rendering), and with `X-Robots-Tag: noindex`.
- **Not found**: `/does-not-exist`, requested with `Accept: text/html`, returns 404 with "Page not found" and `href="/"`.
- **Health**: `/api/health` returns HTTP 200, the body `{"status":"ok"}` and `no-store`.
- **Security headers**: all four are present on `/`, `/playground` and `/api/health`.

Only the unknown-playground-path scenario needs a browser. It is checked by hand (task 3.3).

### D5. CI workflow `.github/workflows/web.yml` (A18)

It triggers on `push` to `main` and on `pull_request`, with paths `apps/web/**`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` and the workflow file itself. There is one job, `web-build`, with `permissions: contents: read`:
1. `actions/checkout@v7`.
2. `pnpm/action-setup@v6`, which reads the version from `packageManager`.
3. `actions/setup-node@v7` with Node 26 and the pnpm cache.
4. `pnpm install --frozen-lockfile`.
5. `typecheck`.
6. `test`.
7. `build`.

The action majors are the latest releases on 2026-11-22 (checkout v7.0.1, setup-node v7.1.0, pnpm/action-setup v6.1.1).

### D6. Vercel (owner actions, documented in `apps/web/README.md`)

- Import the GitHub repository as a new Vercel Hobby project.
- Root Directory: `apps/web`. The Nuxt preset is detected.
- Production branch: `main`. Preview deployments come from pull requests, which is Vercel's default.
- Node.js 26.x comes from `engines.node` in `apps/web/package.json`.
- Environment variable `ENABLE_EXPERIMENTAL_COREPACK` = `1`. It is a build flag, not a secret. It makes Vercel use exactly the pnpm from `packageManager`, instead of guessing from the lockfile format (`lockfileVersion: '9.0'`, which Vercel maps to pnpm 9 or 10).
- Enable "Skip deployments when there are no changes to the root directory or its dependencies", so pull requests that touch only services or docs don't spend builds.
- After the first production deploy, the owner:
  - sets the Supabase Site URL and the redirect URL `https://<app>/auth/callback`;
  - adds the app origin to the Google client's JavaScript origins;
  - adds the hostname to the Turnstile widget.

The agent never runs the `vercel` CLI.

### Free-tier usage

On Vercel Hobby, `/` is a single server-rendered page and `/playground/**` is a static shell. Expected traffic is portfolio-scale, far below Hobby's bandwidth and function-invocation limits. Builds run only when `apps/web` or the workspace changes (D6). CI uses about 3 minutes of GitHub Actions per web pull request, which is free for public repositories. Supabase and Grafana are not touched.

## Risks / Trade-offs

- [Node 26 no longer bundles Corepack] → Install pnpm locally with `npm install -g pnpm@12.21.0`. CI installs pnpm through `pnpm/action-setup`. Vercel provides Corepack through its build flag.
- [Vercel may still pick another pnpm version] → If the Vercel build log shows a pnpm version other than 12.21.0 or an install error, the owner sets the Install Command to `npx -y pnpm@12.21.0 install --frozen-lockfile` and redeploys.
- [A future dependency update adds another build script, and pnpm fails with `ERR_PNPM_IGNORED_BUILDS`] → Add exactly the package the error names under `allowBuilds` in `pnpm-workspace.yaml`, in the PR that adds that dependency.
- [Dependabot may not parse a pnpm 12 workspace] → It fails only inside the Dependabot tab. CI and deploys are unaffected, and the version pins stay manual until it can.
- [The placeholder introduction is visible on the live site until the owner writes it] → It is one string marked `TODO(owner)` in `app/content/profile.ts`, and the README tells the owner where it is.

## Migration Plan

1. Merge the PR after the `web-build` and `gitleaks` checks pass.
2. The owner creates the Vercel project (D6), and its first production deploy builds `main`.
3. The owner opens `https://<app>/api/health`, then sets the Supabase URL configuration, the Google JavaScript origin and the Turnstile hostname.
4. Rollback: use Vercel's "Instant Rollback" to the previous deployment, or revert the merge commit through a new PR. Nothing else depends on the web app yet.

### A17. `apps/web/test/e2e/web.test.ts`

```ts
// Specs: web-routing and web-hosting. Runs against a production build served by the real Nitro server.
import { fileURLToPath } from 'node:url'
import { describe, expect, it } from 'vitest'
import { fetch, setup } from '@nuxt/test-utils/e2e'

await setup({
  rootDir: fileURLToPath(new URL('../..', import.meta.url)),
  server: true,
  build: true,
})

const securityHeaders: Record<string, string> = {
  'x-content-type-options': 'nosniff',
  'referrer-policy': 'strict-origin-when-cross-origin',
  'x-frame-options': 'DENY',
  'permissions-policy': 'camera=(), microphone=(), geolocation=()',
}

describe('web-routing: main page', () => {
  it('is server-rendered with the introduction and a link to the playground', async () => {
    const response = await fetch('/')
    expect(response.status).toBe(200)
    const html = await response.text()
    expect(html).toMatch(/<h1[^>]*>gradiputera<\/h1>/)
    expect(html).toContain('Open the playground')
    expect(html).toContain('href="/playground"')
  })

  it('has a title and a meta description', async () => {
    const html = await (await fetch('/')).text()
    expect(html).toMatch(/<title>[^<]+<\/title>/)
    expect(html).toMatch(/<meta name="description" content="[^"]+">/)
  })

  it('does not send X-Robots-Tag', async () => {
    const response = await fetch('/')
    expect(response.headers.get('x-robots-tag')).toBeNull()
  })
})

describe('web-routing: playground', () => {
  for (const path of ['/playground', '/playground/payment', '/playground/dashboards']) {

      const response = await fetch(path)
      expect(response.status).toBe(200)
      const html = await response.text()
      expect(html).toContain('<div id="__nuxt"></div>')

describe('web-routing: unknown routes', () => {

    const response = await fetch('/does-not-exist', { headers: { accept: 'text/html' } })
    expect(response.status).toBe(404)
    const html = await response.text()
    expect(html).toContain('Page not found')
    expect(html).toContain('href="/"')
  })
})

describe('web-hosting: health endpoint', () => {
  it('returns ok without caching', async () => {
    const response = await fetch('/api/health')
    expect(response.status).toBe(200)
    expect(response.headers.get('cache-control')).toBe('no-store')
    expect(await response.json()).toEqual({ status: 'ok' })
  })
})
```
