# Design

## Context

`services/notification-service/` holds only a README and its OpenSpec folder. The platform layer already provides:
- the `notification` schema, owned by the `notification_service` role (`search_path = notification`). The role cannot reach the other schemas and has no CREATE on the database;
- a local-only role password and a local dispatcher secret (`whsec_` plus base64 of `local-dev-only-notification`) in `supabase/seed.sql`;
- the dispatcher (`supabase/migrations/20261121000300_eventbus_dispatcher.sql`), which signs every delivery with Standard Webhooks:
  - headers `webhook-id`, `webhook-timestamp` and `webhook-signature: v1,<base64 HMAC-SHA256 of "<id>.<timestamp>.<body>">`;
  - the key is the base64 part of the consumer's `whsec_` secret in Vault (`eventbus_webhook_secret_notification`).

payment, ledger and account run on Vercel with the skeleton pattern. ADR 0002 recorded Hono for this service; the owner chose Express (D1).

The local machine has Node.js 26 and npm 11, but no working Docker.

Everything in the Appendix was prototyped on a temporary branch. The `notification-service` workflow passed:
- 17 of 17 tests, none skipped;
- the oasdiff check;
- the Docker build;
- the smoke test, including 401 for an unsigned webhook.

`web-build` also passed with the main-page change. The first prototype run showed that Drizzle's built-in migrator cannot run under the service role (D4).

## Goals / Non-Goals

**Goals:**
- A deployable, tested Express skeleton that validates Supabase tokens, verifies dispatcher signatures, and owns its migrations.
- The `inbox` table ready for idempotent consumption in step 4.
- The framework decision recorded and every Hono mention updated.

**Non-Goals:**
- Event processing, the mail module (templates, caps, masking), sandbox reset logic, guest restrictions, the site fault flag, telemetry, and the dispatcher endpoint configuration.

## Decisions

### D1. Express 5 instead of Hono (owner decision)
The owner prefers Express for Node.js servers. Express 5 (5.3.0):
- passes rejected promises from async handlers to the error handler;
- has `express.text()` for raw bodies;
- is the most widely known Node.js framework.

Hono was recorded in ADR 0002 for its small size and Web-standard APIs, which matter little in a container. ADR 0002 gets an "Amended" line and an updated table row, and the other mentions are updated in this change (the proposal lists them). A separate ADR was offered; the owner chose to fold the decision into this change.

App rules:
- `x-powered-by` is disabled.
- `/events` reads its body with `express.text({ type: () => true, limit: '256kb' })`. The signature covers the exact bytes, so it must not be re-serialised JSON.
- Known paths with another method answer 405; any other path answers JSON 404.
- The error handler answers 413 for oversized bodies and 500 otherwise, with no stack or message from the error.

### D2. Standalone npm project, TypeScript without a build
- **Package manager:** the container builds from `services/notification-service` only (ADR 0003), so the service has its own `package-lock.json` instead of joining the root pnpm workspace, whose lockfile lives outside the build context. npm comes with every Node.js image, so the build needs no extra tool.
- **No build step:** Node 24 strips TypeScript types natively, so `node src/main.ts` runs the sources. This requires:
  - `.ts` import extensions;
  - `erasableSyntaxOnly` and `verbatimModuleSyntax` in `tsconfig.json`, so only strippable syntax is used;
  - `tsc --noEmit` (TypeScript 7) for type checking.

  The image passes `--disable-warning=ExperimentalWarning`.

### D3. JWT validation with jose
`createRemoteJWKSet` fetches `<SUPABASE_URL>/auth/v1/.well-known/jwks.json` with:
- `timeoutDuration` 5 s;
- `cacheMaxAge` 1 h;
- `cooldownDuration` 5 min, so an unknown `kid` triggers at most one refetch every 5 minutes.

`jwtVerify` is called with:
- `issuer` and `audience: 'authenticated'`;
- `algorithms: ['ES256', 'RS256']`, which rejects `none` and HS256;
- `requiredClaims: ['exp', 'sub']`;
- a 30-second `clockTolerance`.

A non-empty string `sub` is checked as well. The middleware stores only `{ userId, anonymous }` in `res.locals`. `docs/security/auth.md` names jose for Node.js.

### D4. Migrations: generated by Drizzle Kit, applied by the service
- **Generation:** `drizzle-kit generate --name create_inbox` produced `drizzle/0000_create_inbox.sql` and its metadata from `src/db/schema.ts`. The tables use `pgTable` without a schema name, so the SQL never creates a schema, and `search_path` places them in `notification`.
- **Why not Drizzle's migrator:** it always runs `CREATE SCHEMA IF NOT EXISTS`, and Postgres checks database-level CREATE before noticing the schema exists. The CI prototype failed with `permission denied for database postgres` (42501). The platform layer owns schemas, so the role must not get that grant.
- **The service's own migrator, `src/db/migrate.ts`:**
  1. reads the same files with `drizzle-orm/migrator`'s `readMigrationFiles`;
  2. takes `pg_advisory_lock` on its single connection;
  3. creates `notification.__drizzle_migrations` in Drizzle's format if it is missing;
  4. applies each migration newer than the last `created_at` in its own transaction, together with its history row.

  It returns the number applied. Closing the connection releases the lock. Drizzle Kit tooling stays compatible with the history table.
- **Connection:** postgres.js with `max: 1`, a 10-second `connect_timeout` and a 30-second `statement_timeout`. The hosted URL uses the session pooler on port 5432.

### D5. `inbox` table
`event_id text primary key`, `event_type text not null`, `received_at timestamptz not null default now()`. Step 4 inserts the event id in the same transaction as any side effect and acknowledges duplicates without repeating them. The table holds no email addresses.

### D6. Webhook signature verification (`src/webhooks/signature.ts`)
- **Secret:** `WEBHOOK_SECRET` must be `whsec_<base64>` with a non-empty key, checked at startup.
- **Headers:** `webhook-id`, `webhook-timestamp` and `webhook-signature` must all be present.
- **Timestamp:** at most 12 digits, and no more than **300 seconds** before or after now, in both directions.
- **Expected value:** `base64(HMAC-SHA256(key, "<id>.<timestamp>.<raw body>"))`.
- **Comparison:** each space-separated `v1,<base64>` value is decoded and compared with `crypto.timingSafeEqual` when its length matches (the length of an HMAC is not secret). Other versions are ignored.

Any failure gets 401 and a log line with only the reason (`missing headers`, `bad timestamp`, `timestamp out of tolerance`, `bad signature`), never the body or the headers. This matches `eventbus.sign`, so step 4 can connect the dispatcher without changing the check.

### D7. Container image
- **Build stage:** `node:24.22.3-trixie-slim` runs `npm ci --omit=dev --ignore-scripts`; no production dependency needs an install script. It then copies `src/` and `drizzle/`.
- **Runtime stage:** `gcr.io/distroless/nodejs24-debian13:nonroot` (same Debian 13 base, no shell), running as a non-root user with `PORT=8080` and `NODE_ENV=production`. The command is `--disable-warning=ExperimentalWarning src/main.ts`.
- **Server timeouts:** `headersTimeout` 10 s, `requestTimeout` 30 s, `keepAliveTimeout` 60 s.
- **SIGTERM:** `server.close()`, `closeIdleConnections()`, and a forced exit after 20 s.

### D8. Tests and CI
- **Unit and HTTP tests** (`node --test`):
  - `verifier.test.ts`: local ES256 and RSA keys with `createLocalJWKSet`;
  - `signature.test.ts`;
  - `app.test.ts`: a real Express server on port 0, a stand-in verifier and a fixed clock.
- **`integration.test.ts`:** skips its suite unless three `NOTIFICATION_TEST_*` variables are set.
- **CI workflow `notification-service`:**
  - setup-node 24 with the npm cache, `npm ci` and the typecheck;
  - `openspec validate` and oasdiff (Docker image);
  - local Supabase, then `npm test`, with the summary required to read `tests 17`, `pass 17` and `skipped 0`;
  - the Docker build, and a smoke test using the local dispatcher secret, derived in the workflow rather than committed.
- **Dependabot:** watches `npm` and `docker` in the service folder.
- **Lockfile:** the plan ships the prototype's exact `package-lock.json` in `assets/`. The local secret appears nowhere as a literal, because gitleaks' generic-key rule flags it. `.env.example` explains how to print it, and the workflow derives it.

## Risks / Trade-offs

- [The migrator is the service's own] → It is about 40 lines, reads Drizzle's own files and keeps Drizzle's history format. The integration tests cover the first run, the no-op rerun and the history row.
- [Type stripping prints an experimental warning on some Node 24 releases] → Silenced in the image. The code uses only erasable syntax, enforced by `tsconfig.json`.
- [Verified events answer 501 until step 4] → Harmless: the dispatcher is not pointed at the service until step 4, and when it is, 501 means "retry later".
- [Root files touched by a service change] → The service's CI wiring, plus the framework-switch documentation the owner asked to fold in. No other root file changes.
- [Local machine without Docker] → Typecheck and the 14 unit and HTTP tests run locally. CI is authoritative for the integration tests, the image and the smoke test.

### A4. `services/notification-service/src/main.ts` (full file)

````ts
import { createJwksVerifier } from './auth/verifier.ts';
import { migrateDatabase } from './db/migrate.ts';
import { createApp } from './http/app.ts';
import { log } from './log.ts';
import { webhookKey } from './webhooks/signature.ts';

async function main(): Promise<void> {
  const { DATABASE_URL, SUPABASE_URL, WEBHOOK_SECRET } = process.env;
  if (!DATABASE_URL || !SUPABASE_URL || !WEBHOOK_SECRET) {
    throw new Error('DATABASE_URL, SUPABASE_URL and WEBHOOK_SECRET must be set');
  }
  const port = Number(process.env['PORT'] || '80');
  const key = webhookKey(WEBHOOK_SECRET);

  const applied = await migrateDatabase(DATABASE_URL);
  log.info('migrations applied', { applied });

  const app = createApp({ verifyToken: createJwksVerifier(SUPABASE_URL), webhookKey: key });
  const server = app.listen(port, () => log.info('listening', { port }));
  server.headersTimeout = 10_000;
  server.requestTimeout = 30_000;
  server.keepAliveTimeout = 60_000;

  // Vercel sends SIGTERM and allows 30 seconds; finish in-flight requests within 20.
  process.once('SIGTERM', () => {
    const force = setTimeout(() => process.exit(0), 20_000);
    force.unref();
    server.close(() => {
      log.info('shut down');
      process.exit(0);
    });
    server.closeIdleConnections();
  });
}

main().catch((err: unknown) => {
  log.error('notification-service stopped', { error: err instanceof Error ? err.message : String(err) });
  process.exit(1);
});
````

### A6. `services/notification-service/src/auth/verifier.ts` (full file)

````ts
import { createRemoteJWKSet, jwtVerify, type JWTVerifyGetKey } from 'jose';

// Validates Supabase Auth access tokens with jose (ADR 0007): the signature with a key from the
// project's JWKS, the algorithm (ES256 or RS256 only), iss, aud (authenticated), exp (required)
// and sub (required).

export const AUDIENCE = 'authenticated';

/** Asymmetric algorithms Supabase signing keys use; none and HS256 are rejected. */
export const ALGORITHMS = ['ES256', 'RS256'];

/** What handlers learn about the caller. It never holds the token itself. */
export interface Identity {
  userId: string;
  anonymous: boolean;
}

export type TokenVerifier = (token: string) => Promise<Identity>;

export function issuerFor(supabaseUrl: string): string {
  return `${supabaseUrl.replace(/\/+$/, '')}/auth/v1`;
}

/** Builds a verifier from any key source; the tests pass a local key set. */
export function createVerifier(keys: JWTVerifyGetKey, issuer: string): TokenVerifier {
  return async (token) => {
    const { payload } = await jwtVerify(token, keys, {
      issuer,
      audience: AUDIENCE,
      algorithms: ALGORITHMS,
      requiredClaims: ['exp', 'sub'],
      clockTolerance: 30,
    });
    if (typeof payload.sub !== 'string' || payload.sub === '') {
      throw new Error('token has no subject');
    }
    return { userId: payload.sub, anonymous: payload['is_anonymous'] === true };
  };
}

/**
 * Fetches signing keys from the Supabase JWKS endpoint: each fetch times out after 5 seconds, keys
 * are cached for an hour, and an unknown key id triggers at most one fetch every 5 minutes.
 */
export function createJwksVerifier(supabaseUrl: string): TokenVerifier {
  const jwks = createRemoteJWKSet(new URL(`${issuerFor(supabaseUrl)}/.well-known/jwks.json`), {
    timeoutDuration: 5_000,
    cacheMaxAge: 60 * 60 * 1_000,
    cooldownDuration: 5 * 60 * 1_000,
  });
  return createVerifier(jwks, issuerFor(supabaseUrl));
}
````

### A7. `services/notification-service/src/webhooks/signature.ts` (full file)

````ts
import { createHmac, timingSafeEqual } from 'node:crypto';

// Standard Webhooks verification, matching the platform dispatcher (eventbus.sign, ADR 0005):
// webhook-signature carries one or more space-separated "v1,<base64 HMAC-SHA256>" values over
// "<webhook-id>.<webhook-timestamp>.<raw body>", keyed with the base64 key of a whsec_ secret.

/** Signed events older or newer than this are rejected, against replay. */
export const TOLERANCE_SECONDS = 5 * 60;

export interface WebhookHeaders {
  id: string | undefined;
  timestamp: string | undefined;
  signature: string | undefined;
}

export type WebhookCheck =
  | { ok: true }
  | { ok: false; reason: 'missing headers' | 'bad timestamp' | 'timestamp out of tolerance' | 'bad signature' };

/** Decodes a whsec_<base64> secret into its key bytes; throws for any other form. */
export function webhookKey(secret: string): Buffer {
  if (!secret.startsWith('whsec_')) {
    throw new Error('WEBHOOK_SECRET must use the whsec_<base64> form');
  }
  const key = Buffer.from(secret.slice('whsec_'.length), 'base64');
  if (key.length === 0) {
    throw new Error('WEBHOOK_SECRET has an empty key');
  }
  return key;
}

export function sign(key: Buffer, id: string, timestamp: number, body: string): string {
  return createHmac('sha256', key).update(`${id}.${timestamp}.${body}`, 'utf8').digest('base64');
}

export function verifyWebhook(key: Buffer, headers: WebhookHeaders, body: string, nowSeconds: number): WebhookCheck {
  const { id, timestamp, signature } = headers;
  if (!id || !timestamp || !signature) {
    return { ok: false, reason: 'missing headers' };
  }
  if (!/^\d{1,12}$/.test(timestamp)) {
    return { ok: false, reason: 'bad timestamp' };
  }
  const sentAt = Number(timestamp);
  if (Math.abs(nowSeconds - sentAt) > TOLERANCE_SECONDS) {
    return { ok: false, reason: 'timestamp out of tolerance' };
  }

  const expected = Buffer.from(sign(key, id, sentAt, body), 'base64');
  for (const candidate of signature.split(' ')) {
    const [version, value] = candidate.split(',', 2);
    if (version !== 'v1' || !value) {
      continue;
    }
    const given = Buffer.from(value, 'base64');
    // timingSafeEqual needs equal lengths; the length of an HMAC-SHA256 is not secret.
    if (given.length === expected.length && timingSafeEqual(given, expected)) {
      return { ok: true };
    }
  }
  return { ok: false, reason: 'bad signature' };
}
````

### A8. `services/notification-service/src/http/app.ts` (full file)

````ts
import express, { type Express, type NextFunction, type Request, type Response } from 'express';
import type { Identity, TokenVerifier } from '../auth/verifier.ts';
import { log } from '../log.ts';
import { verifyWebhook } from '../webhooks/signature.ts';

export interface AppDeps {
  verifyToken: TokenVerifier;
  /** Key bytes of the dispatcher's whsec_ signing secret. */
  webhookKey: Buffer;
  /** Current time in seconds; the tests pass a fixed clock. */
  nowSeconds?: () => number;
}

function error(res: Response, status: number, code: string, message: string): void {
  res.status(status).json({ error: code, message });
}

function notImplemented(_req: Request, res: Response): void {
  error(res, 501, 'not_implemented', 'This endpoint is planned and not implemented yet.');
}

/** The caller's identity, set by the authenticate middleware. */
export function identity(res: Response): Identity {
  return res.locals['identity'] as Identity;
}

export function createApp(deps: AppDeps): Express {
  const now = deps.nowSeconds ?? (() => Math.floor(Date.now() / 1000));
  const app = express();
  app.disable('x-powered-by');

  // Logs method, route, status and duration only: no headers, tokens, bodies or user ids.
  app.use((req, res, next) => {
    const start = performance.now();
    res.on('finish', () => {
      log.info('request', {
        method: req.method,
        route: (req.route as { path?: string } | undefined)?.path ?? 'unmatched',
        status: res.statusCode,
        duration_ms: Math.round(performance.now() - start),
      });
    });
    next();
  });

  const authenticate = async (req: Request, res: Response, next: NextFunction): Promise<void> => {
    const match = /^Bearer\s+(\S+)$/i.exec(req.get('Authorization') ?? '');
    if (!match?.[1]) {
      res.set('WWW-Authenticate', 'Bearer realm="notification-service"');
      return error(res, 401, 'unauthorized', 'missing bearer token');
    }
    try {
      res.locals['identity'] = await deps.verifyToken(match[1]);
    } catch {
      res.set('WWW-Authenticate', 'Bearer realm="notification-service"');
      return error(res, 401, 'unauthorized', 'invalid token');
    }
    next();
  };

  app.get('/health', (_req, res) => {
    res.json({ status: 'ok' });
  });

  // Dispatcher webhooks: only a valid Standard Webhooks signature within the tolerance gets past
  // this point. The raw body is kept as text, because the signature covers its exact bytes.
  // Processing (inbox, email) arrives with roadmap step 4.
  app.post('/events', express.text({ type: () => true, limit: '256kb' }), (req, res) => {
    const check = verifyWebhook(
      deps.webhookKey,
      {
        id: req.get('webhook-id'),
        timestamp: req.get('webhook-timestamp'),
        signature: req.get('webhook-signature'),
      },
      typeof req.body === 'string' ? req.body : '',
      now(),
    );
    if (!check.ok) {
      log.warn('webhook rejected', { reason: check.reason });
      return error(res, 401, 'unauthorized', 'invalid webhook signature');
    }
    notImplemented(req, res);
  });

  // Planned endpoint: authenticated now, implemented by a later change (roadmap step 5).
  app.post('/sandbox/reset', authenticate, notImplemented);

  // Known paths with another method answer 405, everything else 404; errors never leak details.
  app.all(['/health', '/events', '/sandbox/reset'], (_req, res) => {
    error(res, 405, 'method_not_allowed', 'Method not allowed.');
  });
  app.use((_req, res) => {
    error(res, 404, 'not_found', 'No such route.');
  });
  app.use((err: Error & { status?: number; type?: string }, _req: Request, res: Response, _next: NextFunction) => {
    if (err.type === 'entity.too.large') {
      return error(res, 413, 'payload_too_large', 'Request body too large.');
    }
    log.error('unhandled error', { error: err.message });
    error(res, 500, 'internal_error', 'Internal error.');
  });

  return app;
}
````

### A10. `services/notification-service/src/db/migrate.ts` (full file)

````ts
import { fileURLToPath } from 'node:url';
import { readMigrationFiles } from 'drizzle-orm/migrator';
import postgres from 'postgres';

const MIGRATIONS_FOLDER = fileURLToPath(new URL('../../drizzle', import.meta.url));

/** Opens one connection as the notification_service role, with timeouts. */
export function connect(databaseUrl: string) {
  return postgres(databaseUrl, {
    max: 1,
    connect_timeout: 10,
    idle_timeout: 5,
    onnotice: () => {},
    connection: { statement_timeout: 30_000, application_name: 'notification-service' },
  });
}

/**
 * Applies pending Drizzle Kit migrations (drizzle/) to the notification schema and returns how many
 * ran. The history table, notification.__drizzle_migrations, has Drizzle's own format.
 *
 * Drizzle's built-in migrator always runs CREATE SCHEMA IF NOT EXISTS, which needs CREATE on the
 * database; the service role rightly lacks it (the platform layer owns schemas). So this applies the
 * same files itself:
 * - a Postgres advisory lock serialises concurrent cold starts;
 * - each migration runs in its own transaction, together with its history row;
 * - an up-to-date schema is a no-op.
 */
export async function migrateDatabase(databaseUrl: string): Promise<number> {
  const migrations = readMigrationFiles({ migrationsFolder: MIGRATIONS_FOLDER });
  const sql = connect(databaseUrl);
  let applied = 0;
  try {
    await sql`select pg_advisory_lock(hashtext('notification-service.migrations'))`;
    await sql`create table if not exists notification.__drizzle_migrations (
                id serial primary key,
                hash text not null,
                created_at bigint
              )`;
    const [last] = await sql<{ created_at: string }[]>`
      select created_at from notification.__drizzle_migrations order by created_at desc limit 1`;
    const appliedUpTo = last ? Number(last.created_at) : -1;

    for (const migration of migrations) {
      if (migration.folderMillis <= appliedUpTo) {
        continue;
      }
      await sql.begin(async (tx) => {
        for (const statement of migration.sql) {
          if (statement.trim() !== '') {
            await tx.unsafe(statement);
          }
        }
        await tx`insert into notification.__drizzle_migrations (hash, created_at)
                 values (${migration.hash}, ${migration.folderMillis})`;
      });
      applied += 1;
    }
    return applied;
  } finally {
    // Closing the only connection also releases the session-level advisory lock.
    await sql.end({ timeout: 5 });
  }
}
````

````md
# notification-service

Consumes payment and ledger events through signed webhooks and sends real email. Built with Node.js 24, TypeScript and Express 5, packaged as a container.

## Status

In progress: the service skeleton is in place. It covers health, JWT validation, webhook signature verification, own-schema migrations with the `inbox` table, the container image and CI. `POST /events` and `POST /sandbox/reset` answer `501` after their checks until roadmap steps 4 and 5.

## Responsibilities

- Owns the `notification` schema. Migrations are generated with Drizzle Kit and applied on every start, with the history table (`__drizzle_migrations`) inside the `notification` schema.
- Receives events only through signed webhooks: Standard Webhooks HMAC-SHA256, a timing-safe compare, and a 5-minute timestamp tolerance against replay. It is idempotent through the `inbox` table.
- Sends email through Gmail SMTP for payment outcomes, under the rules in ADR 0014 (roadmap step 4).
- Never logs full email addresses, SMTP credentials, tokens, signatures or webhook bodies; no SMS.

## Data model

| Table | Holds |
|---|---|
| `inbox` | `event_id` (primary key), `event_type`, `received_at`: event ids already processed |

## API

The contract is [contracts/openapi/notification.yaml](../../contracts/openapi/notification.yaml).

| Endpoint | Authentication | Now |
|---|---|---|
| `GET /health` | none | `200` with `{"status":"ok"}` |
| `POST /events` | webhook signature | `401` for a missing, wrong or stale signature; `501` once verified (planned: consume the CloudEvent) |
| `POST /sandbox/reset` | bearer token | `501` (planned: delete the caller's rows and stored addresses) |

Webhook signature (Standard Webhooks, the format the dispatcher in `supabase/` uses):
- headers `webhook-id`, `webhook-timestamp` (Unix seconds) and `webhook-signature` (one or more space-separated `v1,<base64>` values);
- the signature is HMAC-SHA256 over `<webhook-id>.<webhook-timestamp>.<raw body>`, keyed with the base64 key of the `whsec_` secret;
- the comparison is timing-safe, and timestamps more than 5 minutes away from now are rejected.

Tokens are Supabase Auth access tokens, validated with `jose` (ADR 0007):
- the signature is checked with keys from `<SUPABASE_URL>/auth/v1/.well-known/jwks.json`;
- only ES256 or RS256 are accepted;
- `iss` must be `<SUPABASE_URL>/auth/v1`, and `aud` must be `authenticated`;
- `exp` and `sub` are required.

A missing or invalid token gets `401` with `WWW-Authenticate: Bearer`. Every error response is JSON.

## Events

- Publishes: none.
- Consumes: `payment.succeeded.v1`, `payment.failed.v1` (queue `payment.events.notification`). Planned.

## Mail module

These rules arrive with roadmap step 4:
- It is triggered only by consumed events. No endpoint sends mail on request.
- Templates are fixed. The user controls only the amount and currency; there are no free-text bodies.
- Every email has a "sandbox demo" footer.
- Caps are 3 emails per user per day and 100 emails globally per day. The module refuses to send when a cap is reached, and the payment is unaffected.
- Failures are logged without the address and never fail the payment.
- Optional IMAP polling reads bounces, so the timeline shows delivered or bounced.

## Masking and retention

- Telemetry shows masked addresses only, for example `j***@gmail.com`.
- Addresses are stored only in the `notification` schema.
- Addresses are deleted on sandbox reset and in the nightly cleanup.

## Configuration

| Variable | Meaning |
|---|---|
| `PORT` | Listening port. Default `80`; the container image sets `8080`. |
| `DATABASE_URL` | `postgres://user:password@host:port/database?params` for the `notification_service` role. URL-encode special characters in the password. |
| `SUPABASE_URL` | Supabase project URL, used for the JWKS endpoint and the expected issuer. |
| `WEBHOOK_SECRET` | The dispatcher's signing secret for this consumer group, in the `whsec_<base64>` form. |

[.env.example](.env.example) has local values. Copy it to `.env` for local runs; `.env` is gitignored.

Outbound calls and their timeouts:
- **JWKS fetch:** 5 seconds. Keys are cached for an hour, and an unknown key id triggers at most one fetch every 5 minutes.
- **Database:** 10-second connect timeout and 30-second statement timeout.

## Owner setup (hosted)

These are owner actions. Agents never run them.

1. **Role password.** In the Supabase dashboard, open the SQL editor and set a strong password for the role:
   ```sql
   alter role notification_service password '<strong-random-password>';
   ```
   Keep it only in Vercel.
2. **Webhook secret.** Use the same value you stored in Vault as `eventbus_webhook_secret_notification` (`supabase/README.md`, "Hosted setup"). You can read it back in the SQL editor:
   ```sql
   select decrypted_secret from vault.decrypted_secrets where name = 'eventbus_webhook_secret_notification';
   ```
3. **Vercel project.** Import the repository as a new project:
   - Root Directory: `services/notification-service`;
   - framework: Container (`vercel.json` selects it).

   Add these Production environment variables:
   - `PORT` = `8080`;
   - `SUPABASE_URL` = `https://<project-ref>.supabase.co`;
   - `DATABASE_URL` = the **session pooler** URL (port 5432) with the role as user: `postgres://notification_service.<project-ref>:<password>@<pooler-host>:5432/postgres?sslmode=require`;
   - `WEBHOOK_SECRET` = the value from step 2.

   Use session mode, not transaction mode (port 6543): the migrations take a session-level advisory lock.
4. **Check.** After the deploy:
   - `https://<notification-project>.vercel.app/health` returns `{"status":"ok"}`;
   - `POST /events` without a signature returns `401`;
   - `POST /sandbox/reset` without a token returns `401`.

The dispatcher's endpoint URL for the `notification` consumer is set in roadmap step 4, when the service starts processing events.
````
